# 官方 rc24 同步计划

## 目标

逐项审查官方 `rc23..rc24` 的运行时代码、前端代码和测试变化，结合当前分支的本地计费、异步任务、权限和 `web/default` 定制，移植有实际价值且风险可控的修复与功能。

## 范围判断

1. **请求体透明重试**：手工适配官方 HTTP/2 `GetBody` 修复，保持请求体可重复读取，并补充回归测试。该项与上游连接被 `REFUSED_STREAM`/`GOAWAY` 重置时的重试直接相关，但不替代 SSE 已返回 200 后的流式错误处理。
2. **用户级关键限流**：对照现有限流中间件、认证顺序和路由，确认是否缺少 access token 与推广转移接口的用户维度保护；仅在不改变既有限流语义时适配。
3. **渠道模型分类**：把官方更准确的模型分类规则适配到当前 `web/default` 的拉取模型界面，避免复制 classic 前端实现。
4. **兑换码精度**：对照 `web/default` 的金额输入和格式化逻辑，确认官方修复是否仍适用；只修复实际存在的精度损失，不改数据库字段。
5. **原生 Claude/Gemini 渠道测试**：与当前已经定制的 endpoint 规范化逻辑对比，已有等价行为则只补缺失测试。
6. **用户/路由 merge、CI 同步**：审查后若与当前销售权限、发布流程或本地定制冲突，则明确不移植。

## 执行方式

- 按垂直切片实施：每个切片先写回归测试，再做最小实现，随后运行定向测试和格式检查。
- 不修改数据库迁移，不覆盖工作区已有修改，不创建提交或推送。
- 最终运行受影响 Go 包测试、前端类型检查/构建和 `git diff --check`，并记录未同步项目及原因。

# 客户端断开后的流式 Token 结算

## Overview

修复客户端主动断开流式请求后的计费结算：保留上游已返回的 usage；若 usage 尚未返回，则使用本地已经收到的输出内容估算输出 Token；如果没有任何输出，记录输入 Token 但整次请求免计费。同时移除面向客户展示的内部免计费提示，不改变数据库结构和渠道重试/熔断机制。

## Architecture Decisions

- 结算优先级固定为：上游 usage > 本地部分响应估算；完全没有输出时保留输入统计但费用为零。
- 客户端断开只影响下游写入，不改变既有渠道重试和熔断边界；本次仅调整结算数据，不在流扫描器中引入后台排空。
- 不新增数据库字段；内部审计继续使用现有管理员信息和流状态字段。
- 客户日志内容不写入计费判断，管理员仍可通过 Token 来源和流状态判断请求结果。

## Task List

### Phase 1: Billing behavior
- [x] 调整客户端断开后的文本用量结算，保留本地累计输出 Token，并保证无输出时整次请求免计费。
- [x] 保持上游 usage 优先，避免本地估算覆盖真实 usage。

### Phase 2: User-visible output
- [x] 删除客户可见的内部免计费/未获取 usage 提示。
- [x] 保留历史日志兼容，管理员审计字段不因前端隐藏而丢失。

### Phase 3: Verification
- [x] 增加客户端断开场景的结算单元测试。
- [x] 增加流式部分输出估算测试，运行后端相关测试和前端类型检查。

## Risks and Mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| 上游 usage 与本地估算不一致 | 重复或少计费 | 只有未获得有效上游 usage 时才使用本地估算 |
| 客户端断开且没有输出 | 可能错误扣费 | 保留输入统计，但强制最终费用为零 |
| 内部字段暴露给普通用户 | 泄露平台实现细节 | 不再写入 `Content`，管理员字段沿用现有 `admin_info` 机制 |
